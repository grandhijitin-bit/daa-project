Slide 03 // Algorithmic Head-to-Head

Why Greedy Heuristics Fail & DP Wins

INDIVISIBILITY = 0/1 CONSTRAINT
Greedy Strategy (Local Optimum) × UNRELIABLE

The Greedy Blind Spot

Greedy heuristics sort by Highest Total Revenue or Value-Per-Seat Density. Both collapse due to item indivisibility:

Heuristic 1: Sort by Total Revenue

Takes one large group, leaving unfillable seat gaps (fragmentation).

Heuristic 2: Sort by Unit Price ($/seat)

Picks smaller groups with higher density but leaves capacity stranded.

⚠️ In 0/1 Knapsack, Fractional Splitting is strictly prohibited!
Dynamic Programming (Global Optimum) ✓ OPTIMAL PROOF

The DP Global Superpower

DP evaluates all subproblem combinations via overlapping subproblems and optimal substructure:

Principle 1: Overlapping Subproblems

Sub-capacities (e.g., packing 2 seats) are solved once and memoized.

Principle 2: Optimal Substructure

Global maximum flight revenue is composed of optimal solutions to smaller sub-capacities.

✨ Guarantees 100% maximum mathematical revenue across all seat permutations.
Slide 04 // Mathematical Modeling

The 0/1 Knapsack Formal Formulation

BELLMAN RECURRENCE
1. STATE DEFINITION
dp[i][w]

i : First i booking requests considered (1 ≤ i ≤ N). w : Max plane capacity available for this subproblem (0 ≤ w ≤ W). Returns the maximum revenue obtainable under these constraints.

2. BASE CASES
dp[0][w] = $0 0 booking requests considered
dp[i][0] = $0 0 seats remaining on aircraft

Initializes row 0 and column 0 of the DP matrix to zero profit.

3. THE BELLMAN OPTIMALITY EQUATION Decision Branch per Item
dp[i][w] = max &Big( dp[i-1][w] ,   vi + dp[i-1][w - wi] &Big)
(Condition: valid only when group size wi ≤ current capacity w)
Choice 1: REJECT Group i Carry over previous best revenue: dp[i-1][w]
Choice 2: ACCEPT Group i Collect vi + best solution for remaining (w - wi) seats.

Slide 08 // Performance & Scalability

Algorithmic Complexity & Space Optimization

PSEUDO-POLYNOMIAL BOUNDS
BRUTE FORCE SEARCH
O(2N)

Examines all 2N subsets. For N = 40 requests, 240 ≈ 1.09 trillion operations → Server crash.

DP TIME COMPLEXITY
O(N × W)

Pseudo-polynomial: Scales with requests N and capacity W. For N=50, W=180 seats → only 9,000 operations (< 1 ms).

SPACE COMPLEXITY
O(W) 1D Array

Reduces 2D matrix storage O(N×W) to a lightweight 1D array of size W+1. Ultra-fast CPU cache locality in memory.

THE CRITICAL 1D IMPLEMENTATION SECRET: REVERSE TRAVERSAL w = W down to wi
✓ Correct: Right-to-Left (w = W ↓ wi)

Ensures cell dp[w - wi] still holds the value from the previous item iteration, strictly maintaining the 0/1 single-use rule.

× Dangerous Bug: Left-to-Right (w = wi ↑ W)

Overwrites lower cells and re-uses the same booking multiple times within the same flight (accidentally solving Unbounded Knapsack!).
